# Provenance / Authorship Methods for SKILL.md Artifacts (human vs. agent-assisted vs. templated/copied)

Scope note: research conducted 2026-10-17 using ~22 web searches/fetches. Items marked "(uncited — background knowledge)" in Inferences are from general knowledge and must be verified before being stated as fact in the report.

## Q0. What the GitSkills dataset itself provides (data available for every method below)

### Takeaway
GitSkills (arXiv 2608.10906; Destefanis, Graziotin, Vaccargiu, Ortu) is a single SQLite file with 3,797,117 SKILL.md files from 282,200 repos, grouped by content hash into 1,877,981 distinct contents; ~50.5% of files are byte-identical copies, and commit history (incl. bot logins and AI names in Co-authored-by trailers) exists only for 458,548 rows / representatives. This makes exact-copy detection free and commit-trailer labeling feasible, but per-copy history is missing.

### Cited Findings
- 3,797,117 SKILL.md files, 282,200 public repos, 195,841 accounts, collected July 2026; 1,877,981 distinct contents — [GitSkills HF paper page](https://huggingface.co/papers/2608.10906); [arXiv HTML](https://arxiv.org/html/2608.10906)
- Tables: `artifacts` (repo, path, basename, location class, content hash, representative flag; full text, parsed front matter, body size, `has_scripts`, `has_references` for representatives; `content_sha_ok`, front-matter validity flag); `repos` (owner, stars, primary language, fork status, creation date, last-push date); `artifact_siblings` (7,264,865 rows: files beside representative skill, with text under a size cap); `mining_runs` (7 rows) — [arXiv HTML](https://arxiv.org/html/2608.10906)
- History columns (458,548 rows with history): first and last commit dates, author accounts (anonymized keyed one-way codes, marked user vs. bot; bot logins kept), commit count, first and last commit messages — [arXiv HTML](https://arxiv.org/html/2608.10906)
- Emails in commit messages masked, personal names redacted, but "AI assistant names in Co-authored-by trailers are kept" — [arXiv HTML](https://arxiv.org/html/2608.10906)
- "50.5% of the collected files are byte-for-byte copies of another file in the dataset"; representative selection prefers `.claude/skills/` with deterministic tie-break; folder contents and history collected only for the representative copy — [arXiv HTML](https://arxiv.org/html/2608.10906)
- The paper reports no AI-generation/authorship analysis; it poses authorship and reuse ("how many skills agents create or maintain", propagation of copies) as open questions — [arXiv HTML](https://arxiv.org/html/2608.10906)

### Inferences
- Commit trailers are only available in first/last commit messages, not all commits; a skill whose agent-assisted edit happened in a middle commit will be missed → treat trailer signal as high-precision/low-recall.
- Because history exists only for representatives, copy lineage ("who published first") must use `repos.creation_date`/`last_push` for non-representative copies, or re-mine via GitHub API for a sample.
- Anonymized author codes still allow per-author aggregation (e.g., one author producing many near-identical skills = bulk/templated).

### Gaps
- Exact column names for history fields were not visible in the fetched text; the team must inspect the SQLite schema (`.schema`).
- Whether committer (vs author) identity and commit timestamps beyond first/last are stored is unclear.

## Q1. Git / commit-metadata signals and known agent signatures

### Takeaway
Explicit agent signatures (trailers, bot logins, branch prefixes, name suffixes) are the highest-precision provenance signal and are what major MSR studies (AIDev, "Agentic Much?") rely on, but all can be disabled or lost (squash merges, manual commits), so they are strong positive labels and weak negatives.

### Cited Findings — exact signature strings
- Claude Code: commit trailers "Generated with Claude Code" and "Co-Authored-By: Claude <noreply@anthropic.com>" added by default; disabled via `includeCoAuthoredBy: false` / `gitAttribution: false` in `~/.claude/settings.json` or `.claude/settings.json` — [DeployHQ](https://www.deployhq.com/blog/how-to-use-git-with-claude-code-understanding-the-co-authored-by-attribution)
- Claude Code newer `attribution` setting (separate commit/PR keys; empty string removes) deprecates `includeCoAuthoredBy`; attribution takes precedence if both set — [ClaudeLog](https://claudelog.com/faqs/attribution-setting-claude-code/); [Classmethod](https://dev.classmethod.jp/en/articles/claude-code-attribution-setting/). Note: sources disagree on exact key names (`commits`/`pullRequests` vs `commit`/`pr`) and version.
- Bug report (Dec 2025) that `includeCoAuthoredBy: false` was not respected — [GitHub issue #14241](https://github.com/anthropics/claude-code/issues/14241)
- "Agentic Much?" also lists a "Generated by: Claude" trailer and the co-author trailer for Claude Code; `.claude/settings.json` can hide traces — [arXiv 2601.18341](https://arxiv.org/html/2601.18341v1)
- Cursor: trailer "Co-authored-by: Cursor <cursoragent@cursor.com>" auto-added starting ~Jan 27–28 2026 (Cursor 2.4.21), on by default, toggle at Settings > Agents > Attribution — [Cursor forum](https://forum.cursor.com/t/co-author-added-without-consent-and-cant-be-turned-off/150096)
- Cursor IDE/CLI agents add "Made-with: Cursor"; cloud agents commit as "Cursor Agent" identity with human as co-author; CLI opt-out `attribution.attributeCommitsToAgent` in `~/.cursor/cli-config.json`; opt-outs reported ignored on some paths (community-reported, not official docs) — [Cursor forum: disable auto co-author](https://forum.cursor.com/t/disable-auto-co-authored-by-cursor-on-agent-commits-or-make-it-opt-in/168258); [Cursor forum: local executor](https://forum.cursor.com/t/local-executor-ignores-cli-config-attribution-opt-out-forcing-co-authored-by-trailer/167722)
- Cursor cloud agent branch prefix `cursor/` — [Cursor forum](https://forum.cursor.com/t/cloud-agent-custom-branch-prefix-feat-fix-instead-of-cursor-and-commit-author-attribution/163698); [AIDev v1](https://arxiv.org/html/2507.15003v1)
- GitHub Copilot coding agent: every commit authored by Copilot with the requesting human as co-author; commit message includes an `Agent-Logs-Url` trailer (Mar 2026) — [GitHub changelog](https://github.blog/changelog/2026-03-20-trace-any-copilot-coding-agent-commit-to-its-session-logs)
- Copilot: "Co-authored-by:copilot-swe-agent" trailer, `copilot/` branch prefix, Copilot-account authorship, `copilot-instructions.md` — [arXiv 2601.18341](https://arxiv.org/html/2601.18341v1); exact bot login `copilot-swe-agent[bot]` not confirmed in official docs.
- VS Code setting `git.addAICoAuthor` (default "all") adds "Co-authored-by: Copilot" — [heise](https://heise.de/-11279554)
- Squash & merge keeps Copilot as author of the squashed commit — [GitHub community #179983](https://github.com/orgs/community/discussions/179983)
- OpenAI Codex: PR head branch `codex/`, no authorship attribution; Devin: author `devin-ai-integration[bot]`; Copilot `head:copilot/` + user login "copilot"; Cursor `head:cursor/`; Claude Code `"Co-Authored-By: Claude"` in PR body. Start-date filters: Codex 2025-05-16, Devin 2024-12-24, Copilot/Cursor 2025-01-01, Claude Code 2025-02-24 — [AIDev v1 Table 2](https://arxiv.org/html/2507.15003v1)
- aider: appends "(aider)" to git author and committer names (author only when aider authored the change); disable with `--no-attribute-author` / `--no-attribute-committer`; `aider --stats` counts these — [aider git docs mirror](https://git.joshthomas.dev/mirrors/aider/src/commit/d01912574641eebefcdec170e206ea577f183003/website/docs/git.md); [git-commit-aider README](https://cdn.jsdelivr.net/gh/MrOrz/git-commit-aider@master/README.md)
- Config-file signals: `CLAUDE.md`, `.claude/`, `AGENTS.md` (shared by many agents, insufficient alone), `copilot-instructions.md`, `.cursorrules`, `.cursor/`; `CONVENTIONS.md` deliberately excluded as ambiguous — [arXiv 2601.18341](https://arxiv.org/html/2601.18341v1)

### Cited Findings — studies
- AIDev (Li, Zhang, Hassan; MSR'26): 932,791 agent PRs from Codex, Devin, Copilot, Cursor, Claude Code; 116,211 repos; 72,189 devs; cutoff 2025-08-01; curated subset 33,596 PRs from 2,807 repos >100 stars; HF `hao-li/AIDev` — [arXiv 2602.09185](https://arxiv.org/html/2602.09185v1)
- AIDev acceptance (AIDev-pop, >500 stars): Human 76.8%, Codex 65.3%, Devin 48.9%, Copilot 38.2%, Cursor 51.4%, Claude Code 52.5% merged. Limitations: Codex has no attribution; Claude trailer can be disabled; local tools undercounted; no precision/recall reported — [AIDev v1](https://arxiv.org/html/2507.15003v1)
- Watanabe et al. (TOSEM): 567 Claude Code PRs in 157 projects; ~84% merged, ~55% of merged without changes; used mostly for refactoring, docs, testing — [arXiv 2509.14745](https://arxiv.org/html/2509.14745v1)
- "Agentic Much?": 4 heuristic families (file, author, branch, label) for 48 agents; 129,134 projects; file-level adopters 6.39% (7.89% incl. gitignore-only); commit-level detection covers only 58.29% of visible file-level users; adoption estimate 15.85%–22.60%; no precision/recall reported; traces hidden by disabled trailers, gitignored configs, squash merges — [arXiv 2601.18341](https://arxiv.org/html/2601.18341v1)

### Inferences
- Implementable regex set (case-insensitive) over commit messages/author names in GitSkills history:
  `co-authored-by:\s*claude`, `generated with \[?claude code`, `noreply@anthropic\.com`, `generated by:\s*claude`, `co-authored-by:\s*cursor`, `cursoragent@cursor\.com`, `made-with:\s*cursor`, `co-authored-by:\s*copilot`, `copilot-swe-agent`, `agent-logs-url:`, `devin-ai-integration`, `\(aider\)` in author/committer name, bot accounts with `[bot]` suffix (exclude dependabot/renovate/github-actions as non-AI bots).
- Recall is time-dependent: Cursor trailers mostly only exist from late Jan 2026; Claude trailers since ~Feb 2025. Report signal prevalence by month.
- Bulk/burst signals (uncited — design suggestion): one commit adding many SKILL.md files, or an author producing dozens of skills on the same day, suggests either generation or bulk import of a collection; distinguish via near-duplicate check against known collections.
- GPG/Sigstore signatures prove identity of committer, not human vs. AI authorship; low value for this classification.

### Gaps
- Official primary documentation for Codex CLI, Gemini CLI, Windsurf, Amp, OpenHands commit signatures was not retrieved; must be checked (or derived empirically by top-N frequent trailer lines in the dataset — recommended: `Counter` of all `Co-authored-by:` lines and emoji/"Generated with" lines).
- No study reports precision/recall of trailer-based detection; no measured rate of disabled attribution.

## Q2. Text-level AI detection (zero-shot, trained, commercial, stylometric)

### Takeaway
Zero-shot detectors (Binoculars, Fast-DetectGPT) are strong on long prose in-distribution but degrade badly under domain shift, adversarial prompting, short text, and code/structured text; SKILL.md (short, templated markdown, mixed code) is a worst case. Use them only as one weak labeling function, never as the deciding signal; lexical "excess vocabulary" stylometry is cheap and interpretable but population-level.

### Cited Findings
- Binoculars (Hans et al., ICML 2024): ratio of perplexity to cross-perplexity of two related LLMs (base vs instruct, e.g., Falcon-7B pair); >90% of ChatGPT samples detected at 0.01% FPR across news, creative writing, essays; outperforms GPTZero and Ghostbuster per authors — [arXiv 2401.12070](https://arxiv.org/html/2401.12070v3)
- Perplexity-based methods flag memorized text as machine-generated — [Moonlight review](https://www.themoonlight.io/es/review/spotting-llms-with-binoculars-zero-shot-detection-of-machine-generated-text) (secondary)
- Fast-DetectGPT replaces DetectGPT's perturbation with sampling (conditional probability curvature), much faster; evaluated on prose — [arXiv 2310.05130](https://arxiv.org/pdf/2310.05130)
- Practical examination (2412.05139) of RADAR, Wild, T5Sentinel, Fast-DetectGPT, PHD, LogRank, Binoculars: TPR@1%FPR drops to as low as 0% in some settings; moderate prompting efforts evade detection; claims don't hold under practical conditions — [arXiv 2412.05139](https://arxiv.org/abs/2412.05139)
- RAID (Dugan et al., ACL 2024): 6M+ generations, 11 models, 8 domains, 11 attacks; 12 detectors easily fooled by attacks, sampling changes, repetition penalties, unseen models; `raid-bench` package evaluates at 5% FPR — [ACL anthology](https://preview.aclanthology.org/setup/2024.acl-long.674); [PyPI raid-bench](https://pypi.org/project/raid-bench)
- COLING 2025 shared task: >99% accuracy at 5% FPR but only on seen domains/models — [arXiv 2501.08913](https://arxiv.org/pdf/2501.08913)
- Code: existing text detectors ineffective on code due to low-entropy tokens; code-specific DetectGPT variants proposed — [arXiv 2310.05103](https://ar5iv.labs.arxiv.org/html/2310.05103); [PromptLayer summary of Ye et al.](https://www.promptlayer.com/research-papers/uncovering-llm-generated-code-a-zero-shot-synthetic-code-detector-via-code-rewriting)
- OpenAI AI Text Classifier: 26% TPR, 9% FPR, unreliable under 1,000 characters; withdrawn July 2023 — [Decrypt](https://decrypt.co/149826/openai-quietly-shutters-its-ai-text-classifier-due-to-low-accuracy); [AI Business](https://aibusiness.com/responsible-ai/openai-quietly-shuts-ai-plagiarism-detector-tool)
- Detectors misclassify non-native English writing as AI (Liang et al.); ~61% of TOEFL essays flagged per press summary — [arXiv 2304.02819](https://arxiv.org/pdf/2304.02819)
- Frequent ChatGPT users are accurate, robust human detectors of AI text — [arXiv 2501.15654](https://arxiv.org/pdf/2501.15654) (supports expert manual annotation for gold set)
- Excess vocabulary (Kobak et al., Science Advances 2025): 15M PubMed abstracts; words like "delves", "showcasing", "underscores", "potential", "findings", "critical" spiked post-LLM; ≥13.5% of 2024 abstracts LLM-processed (up to 40% in subcorpora); list of ~900 excess words released at github.com/berenslab/llm-excess-vocab — [arXiv 2406.07016](https://arxiv.org/abs/2406.07016v5); [GitHub](https://github.com/berenslab/llm-excess-vocab)

### Inferences
- Implementation (uncited — background knowledge; verify): Binoculars official repo `ahans30/Binoculars` (Falcon-7B / Falcon-7B-instruct; needs GPU ~2×7B), Fast-DetectGPT repo `baoguangsheng/fast-detect-gpt` (can run with smaller models e.g., GPT-Neo-2.7B / gpt-j). For a one-sprint project, compute on a stratified sample (e.g., 2–5k skills) and only on prose body after stripping front matter and fenced code blocks; require ≥ ~200 tokens or abstain.
- Calibrate thresholds on in-domain data: positives = SKILL.md with Claude/Cursor trailers; negatives = pre-Nov-2022 human READMEs/markdown docs (SKILL.md didn't exist pre-2022, so use README/CONTRIBUTING files as proxy) — note domain mismatch.
- Stylometric features (cheap, Python stdlib/regex): rate per 1k words of Kobak excess words + agent-favored words ("comprehensive", "robust", "seamless", "leverage", "ensure"); em-dash (—) rate; emoji count; bold-label bullets (`- **X**:`); heading density; bullet-line ratio; checkmark emoji ✅/❌; "When to use"/"Best practices"/"Examples" boilerplate sections; Title Case headings. Use as features in logistic regression trained on trailer-labeled positives, not as hard rules. Caveat: SKILL.md conventions (skill-creator guidance) themselves induce these styles, so human authors imitating templates will look "AI-like".
- Commercial detectors (GPTZero etc.) — not recommended: cost, API limits, opacity, and Binoculars authors report outperforming them.
- Watermarking (uncited — background knowledge): Claude/GPT text output is not publicly watermark-verifiable (SynthID-Text exists for Gemini, detector not general); not usable here.

### Gaps
- No study found measuring Binoculars/Fast-DetectGPT on short markdown or agent instruction files specifically.
- Ghostbuster and GLTR specifics not retrieved this session (known: Ghostbuster uses weak-LM token probabilities + feature search; GLTR visualizes token rank buckets — uncited).

## Q3. Template / copy detection and lineage

### Takeaway
Layer: (1) exact content hash (already in GitSkills), (2) normalized hash (strip whitespace/front-matter name fields), (3) MinHash-LSH near-duplicates on word shingles, (4) embedding similarity for paraphrase-level reuse, (5) template-fingerprint matching against known scaffolds (skill-creator `init_skill.py` TODO placeholders, Anthropic skills repo), and (6) earliest-commit/creation date to orient lineage edges.

### Cited Findings
- GitSkills content-hash grouping; 50.5% byte-identical copies — [arXiv HTML](https://arxiv.org/html/2608.10906)
- datasketch `MinHashLSH(threshold=..., num_perm=128)`; threshold and num_perm fixed at construction; candidate probability 1-(1-s^r)^b; threshold 0.5 → 25 bands × 5 rows, 0.8 → 9 bands × 13 rows; verify candidates with exact Jaccard; `MinHashLSHEnsemble` for containment (good when a skill embeds a template plus additions) — [datasketch fork README](https://github.com/fpug/datasketch); [mojoauth guide](https://mojoauth.com/security-guides/lsh-in-python)
- skill-creator `init_skill.py <skill-name> --path <dir>` creates SKILL.md template with front matter and TODO placeholders plus example `scripts/`, `references/`, `assets/` dirs — [wikidocs tutorial](https://wikidocs.net/381799); skill structure guide — [instagit](https://instagit.com/anthropics/skills/what-is-the-structure-of-a-skill-folder-and-skill-md-file)
- skill-creator itself is widely re-published (many mirrors on skills.sh from different orgs) — [skills.sh wiztral](https://skills.sh/wiztral/agent-skills/skill-creator); [skills.sh bytedance](https://skills.sh/bytedance/deer-flow/skill-creator)

### Inferences
- Recommended pipeline (uncited parameters, standard practice): normalize (lowercase, collapse whitespace, strip YAML `name:`), 5-word shingles, MinHash num_perm=128, LSH threshold 0.8 for "near-copy", 0.5 for "derived"; cluster via union-find. Embeddings: `sentence-transformers/all-MiniLM-L6-v2` cosine ≥0.9 for paraphrase-level matches (chunk long files, 256-token limit).
- Template fingerprints: regex for leftover scaffold text (e.g., "TODO", "[TODO:", placeholder descriptions), presence of empty `scripts/`/`references/`/`assets/` siblings with example files (from `artifact_siblings`) → "scaffold-generated" label (note: skill-creator runs inside Claude, so scaffolded skills are often also agent-assisted — allow multi-label).
- Lineage: within a cluster, earliest `first_commit_date` (or `repos.creation_date` fallback) = likely origin; mark others "copied". Forks (`repos.fork`) should be excluded or labeled "fork-copy". Clock skew/rebased history can falsify dates — use as weak signal.
- Reference corpus: hash anthropics/skills, openai skills, and popular collections; any match = "copied from known collection".

### Gaps
- Verbatim init_skill.py template text not retrieved; team should fetch `skills/skill-creator/scripts/init_skill.py` from github.com/anthropics/skills and fingerprint it.
- SimHash and code clone tools (e.g., NiCad, SourcererCC) not researched this session.

## Q4. Repository-level / contextual signals

### Takeaway
Presence of agent config files (CLAUDE.md, .claude/, AGENTS.md, .cursor/, .cursorrules, copilot-instructions.md) indicates agent use in the repo (file-level adoption 6–8% of projects per "Agentic Much?") — useful as a prior, not proof that the SKILL.md was generated.

### Cited Findings
- File-based heuristics and their caveats (AGENTS.md shared/ambiguous, gitignored configs hide adoption, commit-level detection catches only ~58% of file-level users) — [arXiv 2601.18341](https://arxiv.org/html/2601.18341v1)
- GitSkills `repos` table has fork status, creation date, last push; `artifact_siblings` lists neighboring files — [arXiv HTML](https://arxiv.org/html/2608.10906)

### Inferences
- Features: has_CLAUDE_md (check via siblings only if within skill folder; otherwise needs GitHub API), skill-added-date minus repo-creation-date (skill added on day 0 with many skills → bulk import/collection repo), repo is fork, number of skills in repo, stars.
- Licence provenance (uncited): a LICENSE copied from Anthropic's skills repo (Apache-2.0 header text / "© Anthropic") is a copy signal.

### Gaps
- Root-level repo files (CLAUDE.md at repo root) may not be in GitSkills; needs API sampling.

## Q5. Supply-chain provenance standards applicability

### Takeaway
Gitsign/Sigstore, SLSA, in-toto, and GitHub artifact attestations attest *who/what pipeline* produced or signed an artifact, not whether text was human- or LLM-written; essentially none of the existing skills will carry them, so they are out of scope for classification but worth recommending as future practice.

### Cited Findings
- Gitsign: keyless commit signing via OIDC identity, cert from Fulcio, logged in Rekor; `gpg.format x509`, `gpg.x509.program gitsign`; verify with `git verify-commit` — [Chainguard](https://chainguard.dev/unchained/keyless-git-commit-signing-with-gitsign-and-github-actions); [Sigstore docs](https://docs.sigstore.dev/cosign/signing/gitsign)
- GitHub artifact attestations bind artifact digest to SLSA build provenance predicate in in-toto format, signed with short-lived Sigstore certs; needs `id-token: write`, `attestations: write`; `actions/attest-build-provenance` v4 wraps `actions/attest`; verify with `gh attestation`; free plans: public repos only — [GitHub docs](https://docs.github.com/actions/security-guides/using-artifact-attestations-to-establish-provenance-for-builds); [GitHub blog](https://github.blog/enterprise-software/devsecops/enhance-build-security-and-reach-slsa-level-3-with-github-artifact-attestations/)

### Inferences
- A SKILL.md could be attested as an artifact (digest + provenance), and a custom in-toto predicate could record "generated-by: model X" — but this is self-declared, like trailers.
- C2PA content credentials target media (images/video/audio); text support is minimal (uncited); SPDX/SBOM records license/supplier, could encode skill origin in skill registries (uncited).
- Commit verification status (GitHub "Verified") only exists via API; not in GitSkills.

### Gaps
- No evidence found of any skill registry using attestations; C2PA/SPDX applicability not researched with sources.

## Q6. Validation without ground truth

### Takeaway
Build a silver-standard set from high-precision signals (agent trailers/bot logins → agent-assisted; exact/near-duplicate of an earlier known source → copied; pre-Nov-2022 markdown → human proxy), combine weak signals with Snorkel-style labeling functions (majority vote baseline + LabelModel), and validate on a manually annotated stratified sample (2+ raters, Cohen's kappa), reporting coverage/conflict per signal.

### Cited Findings
- Snorkel LFs vote a label or abstain; LabelModel learns LF accuracies/correlations from agreements/disagreements and beats majority vote when LF accuracies are heterogeneous; `MajorityClassVoter` baseline; redundant/correlated LFs violate independence — [Snorkel docs](https://docs.snorkel.ai/docs/0.94/user-guide/data-dev/labeling-functions-lfs-overview/introduction-to-labeling-functions-lfs); [MetricGate](https://metricgate.com/docs/weak-supervision-snorkel/); [snorkel API](https://snorkel.readthedocs.io/en/v0.9.0/packages/_autosummary/labeling/snorkel.labeling.MajorityClassVoter.html)
- Prior MSR studies report no precision/recall for trailer heuristics, so the project's manual validation would be a contribution — [AIDev v1](https://arxiv.org/html/2507.15003v1); [arXiv 2601.18341](https://arxiv.org/html/2601.18341v1)
- Heavy ChatGPT users are reliable annotators of AI text — [arXiv 2501.15654](https://arxiv.org/pdf/2501.15654)
- Detector evaluation should report TPR at fixed low FPR (1%/5%) — [arXiv 2412.05139](https://arxiv.org/abs/2412.05139); [raid-bench](https://pypi.org/project/raid-bench)

### Inferences
- Plan: (1) LFs: trailer regex (AGENT), bot login (AGENT), exact-hash cluster non-earliest (COPIED), MinHash≥0.8 to earlier file (COPIED), scaffold TODO fingerprint (TEMPLATED), stylometric LR score high/low (AGENT/HUMAN weak), Binoculars score on sample (AGENT/HUMAN weak), repo has agent config (AGENT weak). (2) `PandasLFApplier` → `LFAnalysis` (coverage, overlaps, conflicts). (3) Hold-out evaluation: hide trailer LF, measure how well remaining signals recover trailer-labeled skills (recall proxy). (4) Manual sample ~200 stratified by predicted class, 2 raters, Cohen's kappa via `sklearn.metrics.cohen_kappa_score` (target ≥0.6), resolve disagreements. (5) Calibration: reliability diagram / Brier score via `sklearn.calibration.calibration_curve`.
- Pre-ChatGPT negatives: SKILL.md format is post-2025, so no pre-2022 SKILL.md exists; use pre-Nov-2022 README.md/docs as a domain-proxy human set and explicitly flag domain mismatch.
- Absence of a trailer must NOT be a HUMAN label (attribution often disabled; Codex never attributes).

### Gaps
- No published labeled dataset of human vs. AI SKILL.md found; inter-rater reliability for AI-authorship judgments of technical markdown not found in literature.
