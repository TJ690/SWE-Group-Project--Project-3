# Independent reuse and agent-involvement evidence

```bash
python -m skillsig label --only evidence
python -m skillsig export
```

This reporting layer uses the existing features and v2.1 disclosure flag. It does not
change historical labels, their confidence, the annotation key, or either annotator's
answers. A file can have both reuse evidence and disclosed agent involvement. That is
co-occurrence, not a contradiction, and this output applies no confidence penalty.
Independent here means separate reporting axes, not statistical independence.

## Reuse evidence

The row-level output retains five overlapping flags:

| Flag | Definition and interpretation |
|---|---|
| `flag_exact_content_shared` | At least two dataset files have the same `file_sha`. Equal bytes show sharing, not who copied whom; the original can also be included. |
| `flag_registry_exact` | Exact registry match, excluding the representative marked as registry origin by the existing rules. |
| `flag_registry_near` | Registry near-match with measured Jaccard at or above the configured minimum; known registry origin excluded. A missing similarity does not qualify. |
| `flag_near_duplicate_cluster` | Component size at least two at the primary LSH setting. Components contain candidate links and may chain; this does not guarantee pairwise similarity or common provenance. |
| `flag_scaffold` | Non-null measured scaffold basis: placeholders, masked text, shared lines or outlines. Candidate structural evidence; manual validation is incomplete. |

`reuse_signal` is a compact display category, ordered as exact sharing/registry exact,
near-match/cluster, scaffold only, no signal observed, then reuse not assessed. All
underlying flags remain available: a display category does not erase another signal.
Flags are not additive.

This records the presence of reuse evidence rather than the older **highly templated**
decision. Exact sharing starts at two files and cluster evidence at two members, not
the historical ten-copy/ten-member threshold. The resulting counts must not be described
as additional validated templated labels. A singleton registry origin alone is not
classified as a reused copy. `reuse_not_assessed` means neither template nor scaffold
text coverage exists and no exact-sharing evidence was found, not a unique original.

## Agent-involvement evidence

| `agent_signal` | Meaning |
|---|---|
| `disclosed` | Existing v2.1 `flag_disclosed_agent`: first/last extended trailer or coding-agent bot, with history fetched. |
| `no_disclosure_observed` | History fetched, but no such signal in the available first/last commit view. Does not establish human authorship. |
| `history_unavailable` | Commit history was not fetched; disclosure status cannot be assessed. |

First/last disclosure flags, coding-agent-bot status and bulk-commit context remain
separate columns. Disclosure can concern installation, synchronization or maintenance,
not original writing. No bulk exclusion is applied to the fact that a disclosure was
observed. No human-authorship category is assigned by this reporting layer.

## Inputs and outputs

Inputs: v2.1 labels and flags; v1 copy counts; commit features; template matches;
primary-threshold clusters; scaffold features. Each unique source key is checked, all
labelled skills must have copy/commit coverage, and disclosure flags must agree with
their commit inputs. `--dev-sample` restricts IDs using `s0_devsample_ids.parquet`.

| Output | Contents |
|---|---|
| `src/data/derived/s3_evidence.parquet` | One row per distinct skill: both dimensions, all flags, context, historical label/basis/conflict for audit |
| `results/s3_evidence_matrix.csv` | All 15 reuse × agent combinations, counts, share of all skills and share within each agent column |
| `results/s3_evidence_signals.csv` | Overlapping flag counts by agent status; do not sum across flags |
| `results/s3_evidence_legacy_crosstab.csv` | Historical label × both dimensions |
| `results/s3_evidence_summary.json` | Population totals, overlap and interpretation notes |
| `figures/report/f0_evidence_dimensions.png` | Matrix of counts and column-normalized shares, generated by export |

All generated outputs have input/config manifests. As elsewhere in the pipeline, use
`--force` after changing code. Independent annotations still assess the historical
taxonomy; their precision figures do not validate these new dimensions. That requires
a separate evaluation aligned with the evidence shown.
