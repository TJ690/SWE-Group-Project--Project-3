persona: Hiccup

“I just want to know who wrote a skill before my team starts using it.”

Background

Occupation: Lead application developer

Technology level: Expert user; reviews code from several developers and uses AI coding agents daily but avoids tools whose output they cannot inspect.

Attributes

  • Security-conscious: Reads every skill script before approving it and watches closely for injection flaws or known vulnerabilities.
  • Keeps skills current: Checks that skills match the latest versions of the team’s tech stack before every release.
  • Innovation-focused: Dislikes repetitive work; prefers skills that add something new over copies of what the team already has.
  • Relies on shared skills: Typically copies skills from official registries or well-known community collections.
  • Evidence-driven: Trusts a label only when they can see how confident it is and why it was given.

Goals

  • Know who wrote it: Find out whether a skill is likely human-authored, agent-assisted, or highly templated before adopting it.
  • Use current skills: Ensure every skill the team uses is on its latest version.
  • Trust the origin: Adopt skills only from sources they trust to avoid copies of copies.
  • See what changed: Quickly review what changed whenever a skill is updated.
  • Maximize efficiency: Label all of the team’s skills in minutes without reading each file by hand.
  • Match the stack: Ensure skills fit the languages, frameworks, and versions in the team’s codebase.
